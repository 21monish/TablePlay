IMPORTANT PRODUCT RULES
-----------------------

1. Run TablePlay Setup once for a fresh server installation.
2. Do not run Setup during normal daily use.
3. Use a newer Setup file only for Upgrade / Repair.
4. Do not uninstall TablePlay before a normal update.
5. Do not manually delete C:\Program Files\TablePlay.
6. Do not install XAMPP on a restaurant computer for TablePlay. The installer
   contains its own PHP, MariaDB, service and required Visual C++ runtime.
7. Keep the TablePlay Cloud private licence-signing key only on the secured
   Super Admin system. Never copy it or the Cloud .env to a restaurant.

The current installer has a verified SHA-256 but is not yet Authenticode-signed.
Windows SmartScreen may therefore show an Unknown publisher warning. Before
commercial public distribution, sign the final EXE with the TablePlay Windows
code-signing certificate and complete acceptance testing on a clean Windows 11
computer.


PART 1 - ONE-TIME SERVER INSTALLATION
-------------------------------------

Use these steps only on the main restaurant laptop.

A. REQUIREMENTS

- Windows 10 or Windows 11 x64
- A Windows Administrator account
- At least one private Wi-Fi router; a phone hotspot is acceptable for testing
- The v2.5.6 installer and its .sha256 file
- Ports 8000, 8080 and 3310 free before a fresh installation
- Laptop connected to power during installation

The installed product uses:

   8000 - TablePlay website and REST API
   8080 - Reverb real-time updates
   3310 - Private MariaDB on 127.0.0.1 only

B. VERIFY THE INSTALLER

Open PowerShell in the folder containing the installer and run:

   (Get-FileHash -Algorithm SHA256 -LiteralPath '.\TablePlay-Setup-v2.5.6.exe').Hash

The result must match the installer checksum listed above. The comparison is
case-insensitive. Do not run the file if the value differs.

C. STOP DEVELOPMENT SERVERS

Before a fresh install, close any XAMPP control panel, development Laravel
server, Reverb server, queue worker or older TablePlay Setup window.

Check for occupied ports:

   Get-NetTCPConnection -State Listen -LocalPort 8000,8080,3310 -ErrorAction SilentlyContinue |
       Select-Object LocalAddress,LocalPort,OwningProcess

If a result appears, identify its process:

   Get-Process -Id PROCESS_ID

Replace PROCESS_ID with the displayed OwningProcess number. Stop only a process
you recognize. Do not terminate Windows system processes.

D. INSTALL

1. Right-click TablePlay-Setup-v2.5.6.exe.
2. Select Run as administrator and approve Windows UAC.
3. Enter the restaurant name.
4. Enter the Administrator email.
5. Create a strong, unique Administrator password of at least 10 characters.
6. Select Install TablePlay.
7. Keep Setup open until database, migrations, release publishing, service
   startup and all health checks finish.
8. Select Launch TablePlay.
9. Sign in with username admin and the password entered during Setup.
10. Store the Admin credential securely.

The installer creates:

   C:\Program Files\TablePlay

It installs the private database, Laravel server, Reverb, queue worker,
scheduler, Windows service, Server Manager, firewall rules, shortcuts, backup
folder and current Staff/Customer packages.

The automatic Windows service is:

   TablePlayServer

Check it in PowerShell:

   Get-Service -Name TablePlayServer

Expected status:

   Running

Check local HTTP health:

   Invoke-WebRequest -UseBasicParsing http://127.0.0.1:8000/up

Expected result:

   StatusCode : 200

E. FIRST ADMIN SETUP

Open:

   http://127.0.0.1:8000/login

Then complete Admin -> Setup:

1. Restaurant identity, contact details, tax and receipt settings
2. Restaurant logo and TablePlay app logo
3. Tables and seating capacity
4. Admin, Counter, Kitchen and Waiter accounts
5. Menu categories, item names, descriptions, prices and photos
6. Licence activation, if a paid plan was supplied
7. Staff/Customer application installation
8. Secure QR pairing for each Customer tablet
9. One complete test order
10. First verified backup


PART 2 - LICENCE ACTIVATION
---------------------------

TablePlay enforces plan features and Customer-table limits on the server.
Activate the correct customer subscription before pairing production tablets.

A. ONLINE ACTIVATION

1. On the secured Super Admin system, create the restaurant customer and
   subscription.
2. Issue a one-time activation key.
3. On the restaurant server, open Admin -> License.
4. Enter the TablePlay Cloud HTTPS URL and the one-time activation key.
5. Select Activate and verify.
6. Confirm the expected plan, expiry, features and table limit.

An activation key is single-use. Issue a new key for a replacement installation
or when the original unused key has been revoked.

B. FULLY OFFLINE ACTIVATION

No Cloud URL or internet connection is required for this method.

1. On the restaurant server, open Admin -> License.
2. Select Create or download request to obtain the signed .tpr file.
3. Move the .tpr file by USB to the secured Super Admin computer.
4. Open Super Admin -> Restaurant Customers -> Offline activation.
5. Select the customer's active subscription and upload the .tpr file.
6. Issue and download the signed .tpl licence file.
7. Move the .tpl file by USB back to the restaurant server.
8. Open Admin -> License and import the .tpl file.
9. Confirm the expected plan, status, limits and expiry.

The offline licence is bound to that installation and device. It rejects
tampered, wrong-device, replayed and older-revision files. Refresh the signed
offline licence at least every 30 days unless the configured lease says
otherwise.


PART 3 - INSTALL STAFF AND CUSTOMER APPLICATIONS
------------------------------------------------

All application downloads are served by the restaurant laptop. Internet is not
required after the server is installed.

Open TablePlay Server Manager and select App QR codes, or open Admin -> Setup.

Download endpoints:

   Staff Android:
   http://LAPTOP_IP:8000/api/v1/app-updates/download/staff-android

   Customer Android:
   http://LAPTOP_IP:8000/api/v1/app-updates/download/customer-android

   Staff Windows:
   http://LAPTOP_IP:8000/api/v1/app-updates/download/staff-windows

A. STAFF WINDOWS

1. Download the Staff Windows ZIP on the staff computer.
2. Verify its checksum.
3. Extract the entire ZIP to a stable folder. Do not run the EXE from inside
   the ZIP and do not copy only the EXE.
4. Run tableplay_staff.exe.
5. If prompted, enter:

      http://LAPTOP_IP:8000/api/v1

6. Sign in with an Admin, Counter, Kitchen or Waiter username and password/PIN.
7. The role-specific workspace opens automatically.

The ZIP also contains tableplay_updater.exe. Keep it beside the Staff
application and use the application's Download and Restart update flow.

B. STAFF ANDROID

1. Scan the Staff Android download QR or open its download endpoint.
2. Allow installation from the browser/local source when Android asks.
3. Install the APK.
4. Use the server API URL and sign in with a Staff account.

C. CUSTOMER ANDROID

1. Confirm the current plan includes the Customer Table app and has an available
   tablet slot.
2. Scan the Customer Android download QR or open its download endpoint.
3. Allow installation from the browser/local source when Android asks.
4. Install and open the Customer app.
5. Do not enter a table code manually. Continue with secure QR pairing below.

D. SECURE CUSTOMER-TABLE PAIRING

Legacy manual device registration and table-code pairing are retired.

1. In Admin -> Setup or Admin -> Tables & devices, choose an active, unpaired
   table.
2. Select Pair QR.
3. On the Customer app select Set up this table -> Scan pairing QR.
4. Scan the QR within 15 minutes.
5. Confirm the correct table number appears in the Customer app.

Each pairing QR works once and expires. Generate a new QR if it expires or was
already used. Customer pairing stays saved until an Admin unpairs the device or
the app is reset. Staff sign-in stays saved until the employee signs out.


PART 4 - PRIVATE NETWORK SETUP
------------------------------

RECOMMENDED PRODUCTION NETWORK

- Use a dedicated private Wi-Fi router.
- Connect the server laptop by Ethernet when possible.
- Connect Staff devices and Customer tablets to the same LAN/Wi-Fi.
- Disable guest mode and AP/client isolation.
- Create a DHCP reservation for the server laptop so LAPTOP_IP remains stable.
- Use strong Wi-Fi and router-admin passwords.
- Do not expose TablePlay or database ports directly to the public internet.

A phone hotspot is suitable for temporary testing but may change the laptop IP,
sleep automatically or prevent connected clients from communicating.

A. FIND THE SERVER LAPTOP IP

On the laptop, open Command Prompt and run:

   ipconfig

Under the active Wi-Fi or Ethernet adapter, find IPv4 Address.

Example only:

   192.168.1.50

Use that address as LAPTOP_IP. Do not keep an old address from this guide.

B. SET THE WINDOWS NETWORK TO PRIVATE

Open PowerShell as Administrator:

   Get-NetConnectionProfile |
       Format-Table InterfaceAlias,Name,NetworkCategory

If the restaurant adapter is not Private, use its exact InterfaceAlias:

   Set-NetConnectionProfile -InterfaceAlias "Wi-Fi" -NetworkCategory Private

This setting normally persists for that Windows network profile. You may need
to set it again only if Windows sees a different hotspot/SSID as a new network,
the profile is reset, or company policy changes it.

C. FIREWALL

Setup creates inbound rules named TablePlay Web and TablePlay Realtime for
Private networks only. Verify them:

   Get-NetFirewallRule -DisplayName "TablePlay Web","TablePlay Realtime" |
       Select-Object DisplayName,Enabled,Profile,Direction,Action

Expected:

   Enabled   : True
   Profile   : Private
   Direction : Inbound
   Action    : Allow

Only TCP 8000 and 8080 should be accessible from the restaurant network.
MariaDB port 3310 must remain bound to 127.0.0.1 and must not have a public
firewall rule.

D. CORRECT ADDRESSES

On the server laptop:

   Website:  http://127.0.0.1:8000
   Health:   http://127.0.0.1:8000/up

On Staff computers, phones and Customer tablets:

   Website:  http://LAPTOP_IP:8000
   API:      http://LAPTOP_IP:8000/api/v1
   Health:   http://LAPTOP_IP:8000/up
   Realtime: ws://LAPTOP_IP:8080

0.0.0.0 is only a server bind address. It is never a browser or application
destination.

E. CONNECTION TESTS

On the laptop:

   Test-NetConnection -ComputerName 127.0.0.1 -Port 8000
   Test-NetConnection -ComputerName 127.0.0.1 -Port 8080

From another Windows device:

   Test-NetConnection -ComputerName LAPTOP_IP -Port 8000
   Test-NetConnection -ComputerName LAPTOP_IP -Port 8080

Expected:

   TcpTestSucceeded : True

On every phone/tablet browser, open:

   http://LAPTOP_IP:8000/up

If /up does not open in the browser, the application will also time out.

F. CHECK LISTENING PORTS

On the laptop:

   Get-NetTCPConnection -State Listen -LocalPort 8000,8080,3310 |
       Select-Object LocalAddress,LocalPort,OwningProcess

Expected:

   0.0.0.0:8000
   0.0.0.0:8080
   127.0.0.1:3310


PART 5 - NORMAL DAILY STARTUP
-----------------------------

1. Start the restaurant router.
2. Start the server laptop and connect it to the restaurant network.
3. Wait approximately one minute.
4. Open TablePlay Server Manager.
5. Confirm Windows service is Running.
6. Confirm Application health is Healthy.
7. Confirm the displayed local IP matches the router reservation.
8. Open the Staff and Customer applications.

Do not run TablePlay Setup every day. TablePlayServer starts automatically with
Windows. If it is stopped, select Start in Server Manager.


PART 6 - REGULAR SERVER UPDATE OR REPAIR
----------------------------------------

Use this process only when a newer trusted TablePlay-Setup-vX.X.X.exe is
provided or the current installation needs repair.

1. Finish or pause active restaurant orders.
2. Open Server Manager and create a verified backup.
3. Copy an important backup to a different computer or external drive.
4. Close Staff Desktop and every old Setup window.
5. Verify the newer Setup EXE against its matching .sha256 file.
6. Right-click the newer Setup EXE and choose Run as administrator.
7. Select Upgrade / Repair TablePlay.
8. Do not uninstall and do not delete C:\Program Files\TablePlay.
9. Wait for backup, payload verification, migrations, service restart and health
   checks to finish.
10. Select Launch TablePlay.
11. Confirm Admin login, licence state, logos, menu photos and device access.
12. Place one complete test order before returning to normal service.

Upgrade preserves restaurant configuration, users, tables, pairings, menu,
orders, payments, game state, uploaded files and published application
packages. Setup makes a verified SQL backup before changing the database and
attempts a safe rollback if an upgrade fails.

If Setup says TablePlay is already installed, use Upgrade / Repair. Do not try
to create a second installation on the same laptop.


PART 7 - REGULAR APPLICATION UPDATES
------------------------------------

Use Admin -> Update Center to publish a trusted newer Staff or Customer release.

ANDROID RULES

1. The application ID must stay unchanged.
2. The APK must use the same production signing certificate.
3. The version code/build number must be higher.
4. Install the new APK over the existing application.
5. Do not uninstall first; uninstalling can remove saved login/pairing data.
6. Never publish debug, corrupted or differently signed APKs.

WINDOWS STAFF RULES

1. Publish the complete Staff Windows ZIP, not only tableplay_staff.exe.
2. Keep tableplay_updater.exe beside the main application.
3. Use Download and Restart when the Staff app offers an update.
4. Confirm the employee remains signed in and the correct dashboard loads.

After every app update:

- Confirm Staff login remains saved until logout.
- Confirm Customer pairing remains saved.
- Confirm menu images and both configured logos load.
- Confirm real-time order and service-request updates.
- Complete one test order and one game-access check when the plan includes games.


PART 8 - BACKUP, RESTORE AND UNINSTALL
--------------------------------------

A. BACKUP

Open:

   TablePlay Server Manager -> Create backup

Create a backup before every server update and at a regular operational
interval. Copy important backups away from C:\Program Files\TablePlay because a
full uninstall may remove local data.

B. RESTORE

1. Stop new restaurant activity.
2. Open Server Manager -> Restore backup.
3. Select only a trusted, compatible TablePlay backup.
4. Review the displayed backup information.
5. Complete the two-step restore confirmation.
6. Wait for maintenance mode, database restore, restart and health verification.
7. Test login, tables, menu, one order and one payment.

C. UNINSTALL

Use Server Manager -> Uninstall TablePlay or the installed uninstaller.
Close TablePlay applications when requested. Do not manually remove the
C:\Program Files\TablePlay folder and do not delete individual runtime DLLs.
Copy required backups to another location before confirming removal of local
data.


PART 9 - TROUBLESHOOTING
------------------------

1. APP SHOWS TimeoutException AFTER 15 SECONDS

- Confirm Server Manager shows Running and Healthy.
- Open http://LAPTOP_IP:8000/up in that device's browser.
- Recheck LAPTOP_IP with ipconfig.
- Confirm both devices use the same private network.
- Confirm the network profile is Private.
- Confirm the TablePlay firewall rules are enabled.
- Disable hotspot AP/client isolation.
- Do not use 0.0.0.0, localhost or 127.0.0.1 on another device.

2. INSTALLATION SAYS REQUIRED PORTS ARE IN USE

Run:

   Get-NetTCPConnection -State Listen -LocalPort 8000,8080,3310 -ErrorAction SilentlyContinue |
       Select-Object LocalAddress,LocalPort,OwningProcess

Identify each PID with Get-Process. Close only the known XAMPP/development or
older TablePlay-owned process, then run Setup again as Administrator.

3. INSTALLER HTTP HEALTH CHECK FAILS

- Do not repeatedly uninstall or manually delete files.
- Open C:\Program Files\TablePlay\logs or select View logs in Server Manager.
- Review setup-commands.log and the newest runtime log.
- Confirm TablePlayServer is Running.
- Confirm ports 8000, 8080 and 3310 have the expected listeners.
- Run http://127.0.0.1:8000/up locally.
- Run the same v2.5.6 installer as Administrator and choose Upgrade / Repair.

4. WINDOWS REPORTS VCRUNTIME140.DLL IS MISSING

Use the complete verified v2.5.6 installer. It bundles Microsoft's signed Visual
C++ x64 Redistributable and installs it before PHP starts. A copied partial
installer/payload or an older build should not be used. Never download a loose
DLL from an unofficial website.

5. ANDROID SAYS THE APK HAS A DIFFERENT SIGNING CERTIFICATE

Use the current published release with the package IDs and certificate
fingerprint listed at the top of this guide. Android cannot install an update
over an older app signed with a different key. Preserving app data is possible
only when the original production signing key is used. If the old app came from
an unrelated/debug key and that key is unavailable, uninstalling and securely
pairing/signing in again is unavoidable.

6. ANDROID SAYS THE APK IS UNSIGNED OR INVALID

- Download it again from the restaurant server.
- Compare its SHA-256.
- Confirm the file is a release APK, not a debug artifact.
- Confirm the complete file downloaded before opening it.

7. QR PAIRING FAILS

- Confirm the plan includes the Customer app and has a free tablet slot.
- Confirm the table is active and not already paired.
- Generate a new Pair QR from Admin.
- Scan within 15 minutes.
- Confirm the tablet can open http://LAPTOP_IP:8000/up.
- Do not use an old screenshot of a QR; every token works only once.

8. PHONE HOTSPOT WORKS ON LAPTOP BUT NOT ON OTHER PHONES

- Enable Allow connected devices to communicate, Device sharing or Local
  network access.
- Disable AP/client isolation or guest isolation.
- Disable automatic hotspot shutdown.
- Temporarily disable mobile data on the testing client.
- Reconnect every device and check the laptop IP again.

9. THE SERVER LAPTOP IP CHANGES

Create a DHCP reservation in the restaurant router using the laptop network
adapter's MAC address. Recreate application configuration/pairing only if the
stored server address changed; a stable reservation prevents this problem.

10. OFFLINE PLAN EXPIRES OR ENTERS A LEASE/GRACE STATE

Generate a fresh .tpr request, issue the current signed .tpl from the secured
Super Admin system, and import it from Admin -> License. Confirm that the
subscription revision, plan and expiry are current.


PART 10 - FINAL ACCEPTANCE CHECKLIST
------------------------------------

Before serving real customers:

[ ] Server Manager shows Running and Healthy
[ ] Laptop IP is reserved and all devices can open /up
[ ] Firewall exposes only 8000/8080 on the Private profile
[ ] Database listens only on 127.0.0.1:3310
[ ] Correct plan, limits and expiry are visible
[ ] Restaurant logo, app logo, favicon and menu photos display
[ ] Every Staff role opens only its permitted workspace
[ ] Every Customer tablet is securely QR-paired to the correct table
[ ] Table limits and feature entitlements are enforced
[ ] Counter can confirm/reject orders and control game time
[ ] Kitchen can move orders through Preparing, Ready and Served
[ ] Waiter can handle requests and take table orders when the plan allows it
[ ] Billing, cash payment, receipt and table closure work
[ ] Games unlock only after order confirmation and lock after expiry/billing
[ ] Staff login persists until explicit logout
[ ] Customer pairing persists until Admin unpair/reset
[ ] Backup creation and a controlled restore test succeed
[ ] App update checks use the latest published releases
[ ] One complete multi-device pilot has passed on the target restaurant network
